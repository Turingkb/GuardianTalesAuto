# MGA 坎公助手

MGA 是基于 **MaaFramework** 自动化引擎和 **MFAAvalonia** 通用桌面界面的《坎公骑冠剑》国服日常助手，适配 `com.bilibili.snake`、1280×720 横屏。当前资源版本 **0.3.1**，验证环境为 Windows x64、MuMu。

> GitHub 的源码 ZIP 不包含运行时；便携运行包由固定版本依赖单独构建。活动与游戏界面可能变化，已验证范围和剩余限制见下文。

## 架构来源与致谢

- [MaaFramework 5.12.3](https://github.com/MaaXYZ/MaaFramework/tree/v5.12.3)：Pipeline、图像/OCR 识别、设备控制、EmulatorExtras 截图，LGPL-3.0。
- [MFAAvalonia 2.16.2](https://github.com/MaaXYZ/MFAAvalonia/tree/v2.16.2)：Avalonia 桌面界面、任务选项、日志、设置、运行后操作，GPL-3.0。
- [MaaAgentBinary](https://github.com/MaaXYZ/MaaAgentBinary)：配套安卓输入辅助组件，AGPL-3.0。
- [M9A](https://github.com/MAA1999/M9A)：任务组织和使用体验的开发参考，AGPL-3.0。

MGA 使用 MaaFramework 与 MFAAvalonia 作为运行架构，维护坎公任务、模板、配置和 Python Agent；M9A 用于开发参考。感谢上游开发者与贡献者；替换程序名称和图标不改变框架来源。完整范围、上游源码及许可见 [第三方声明](THIRD_PARTY_NOTICES.md)。

## 便携运行包

Windows x64 便携包完整解压后双击 `run_gui.bat`，已内置 Python 3.14.10、OCR 模型与框架运行文件，无需另装 Python；仍需 .NET 10 x64 Runtime，启动器会检查并在缺少时提供官方安装指引。首次自行选择模拟器，不预置开发者设备或账号设置。

`GTAssistant.bat --check` 只检查环境。便携包的构建、校验清单及发布步骤见 [便携包说明](dev/portable-release.md)。以下安装步骤面向直接从源码恢复环境的开发者。

## 安装与使用

### 运行要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows x64；当前仅在 MuMu 上验证 |
| 游戏 | 国服 `com.bilibili.snake`，模拟器横屏分辨率 1280×720 |
| Python | 3.10 或以上，`python` 已加入 PATH；开发机使用 3.14，Agent 仅用标准库 |
| .NET | .NET 10 Runtime（Windows x64）；当前 GUI 声明依赖 `Microsoft.NETCore.App 10.0.0` |
| 自动化引擎 / GUI | MaaFramework 5.12.3 / MFAAvalonia 2.16.2 |

在命令行执行 `python --version`、`dotnet --list-runtimes` 可检查运行环境。这里只验证过上述固定框架版本，升级后需要重新验证。

### 准备运行文件

1. 取得本仓库源码，从上文的官方版本链接下载 Windows x64 运行文件。
2. 将 MFAAvalonia 运行包合并至项目根目录，保留本项目的 `interface.json` 和任务资源，不用上游示例资源覆盖它们。
3. 按下列结构放置 MaaFramework 原生库、安卓输入辅助组件及 OCR 模型。GUI 配套的 `libs/`、`runtimes/` 和 DLL 应完整保留，不要只复制 EXE；各组件许可证也须保留。

```text
GuardianTalesAuto/
├─ run_gui.bat
├─ GTAssistant.bat
├─ MFAAvalonia.exe                  # 首次启动时改名为 GTAssistant.exe
├─ MFAAvalonia.dll
├─ MFAAvalonia.deps.json
├─ MFAAvalonia.runtimeconfig.json
├─ interface.json
├─ agent/
├─ libs/MaaAgentBinary/             # 安卓输入辅助组件
├─ runtimes/win-x64/native/         # MaaFramework 原生 DLL
└─ resource/
   ├─ pipeline/
   ├─ image/
   └─ model/ocr/                   # det.onnx、rec.onnx、keys.txt
```

详细路径见 [环境恢复说明](dev/repository-setup.md)。目录树只列出关键文件，不是完整运行包清单。本仓库不包含 GUI 二进制和 OCR 模型，直接双击源码目录不能代替上述准备。

### 首次运行

1. 启动模拟器，设置 1280×720 横屏并确认游戏能手动进入大厅。
2. 双击 `run_gui.bat`。首次导入时启动器会将 `MFAAvalonia.exe` 改名为 `GTAssistant.exe`；配套 DLL 保留原名。
3. 在 GUI 选择自己的 ADB 设备，核对 MuMu 安装目录、实例与端口。首次发现设备后如未连接，点击重新连接。
4. 首次建议只勾选“启动并返回大厅”检查连接，再配置需要的任务和商品。
5. 点击“开始任务”。新配置默认勾选 10 项日常；可选体力副本默认关闭，收费商品默认购买次数为 0。已有配置继续保留用户的勾选和数量。

不要让 GUI、CLI、其它脚本或开发工具同时控制同一模拟器。Python 命令名称不同的电脑，需要同时调整 `interface.json` 的 `agent.child_exec` 和 `GTAssistant.bat`。

### 更新已有安装

更新源码后，在方便时退出助手，再通过 `run_gui.bat` 启动；启动器会迁移旧任务缓存并保留已有设置。直接双击 EXE 不会运行这一步迁移。助手已经打开时，再运行启动器也不会刷新当前窗口的选项定义。

## 功能

共 **21 项任务，默认 10 项**。游戏内“已领取”或“免费次数用完”可正常跳过；未知页面、费用异常和无法确认的结果会停止相关任务并保留日志。

| 任务 | 默认 | 范围 |
| --- | --- | --- |
| 启动并返回大厅 | 开 | 启动游戏，处理已识别的公告、推广及奖励弹窗 |
| 签到检查与领取 | 开 | 检查签到，签到前后收取浮游城灵魂点；已签到也收取 |
| 公会签到 | 开 | 公会签到及已适配排名结算 |
| 商店购买 | 开 | 默认每日免费金币；收费商品需勾选并填写次数 |
| 活动商店购买 | 关 | 独立商品勾选；未开放或售罄跳过 |
| 邮箱自动领取 | 开 | 系统与通知邮件、领取确认 |
| 好友一键领取与送礼 | 开 | 领取礼物并向现有好友送礼 |
| 通用日常扫荡 | 开 | 觉醒、忒提斯各自剩余免费次数，各最多 3 次；无免费次数跳过 |
| 进化石副本扫荡 | 关 | 次数、焕发限制、起始属性、自动选英雄或沿用游戏设置 |
| 金币副本扫荡 | 关 | 设置 0～100 次，默认只用焕发次数 |
| 经验副本扫荡 | 关 | 设置 0～100 次，默认只用焕发次数 |
| 道具副本扫荡 | 关 | 设置 0～100 次，默认只用焕发次数 |
| 红色碎片副本扫荡 | 关 | 保留焕发限制入口；没有焕发则默认跳过 |
| 开花石副本扫荡 | 关 | 次数与属性，奖励英雄沿用游戏设置，每次 10 体力 |
| 领取已完成的日常奖励 | 开 | 日常任务、活跃度奖励，返回大厅后领取可用的小公主宝箱 |
| 活动奖励领取 | 开 | 已适配“开心宾果乐”的任务积分；不抽奖、不兑换 |
| 领取通行证奖励 | 开 | 邀请赛目标经验、已解锁奖励；不购买或跳级 |
| 活动页面（查看） | 关 | 只打开列表供手动查看，不执行挑战或兑换 |
| 冷启动游戏（维护） | 关 | 停止后重新启动游戏 |
| 全屏 OCR 探测（调试） | 关 | 只识别当前画面，不点击 |
| 关闭游戏 | 关 | 只关闭坎公，保留模拟器和助手 |

推荐顺序：签到／商店／邮箱／好友 → 扫荡 → 日常奖励 → 活动奖励 → 通行证奖励 → 关闭游戏。任务可以拖动排序。

## 扫荡设置

次数范围为 0～100，0 次跳过。进化石、金币、经验和道具副本共用每日 10 次焕发额度，默认只使用剩余额度，任务顺序决定额度分配。红色碎片保留焕发限制入口，未检测到焕发时默认跳过。关闭焕发限制后会消耗普通体力；游戏可能同时扣除备用体力，提交前会核验总消耗。免费觉醒和忒提斯不会使用付费挑战次数。

进化石“自动选英雄”从起始属性开始，仅选择已持有英雄；满星或累计达到 1160 个进化石时更换目标。每次扫荡后重新检查，当前属性没有目标时按虚→光→暗→土→火→水轮换，不执行英雄进化。“沿用游戏设置”只刷所选属性，需先在游戏奖励设置的齿轮中选好英雄。

开花石按所选属性与次数运行，不自动更换奖励英雄。两项副本各自保存次数和属性，不互相覆盖。

## 商店设置

资源提供体力、每日免费金币；英雄成长提供传说觉醒石；装备提供强化锤。钻石商店和活动商店保留预设商品及备用自定义商品。勾选商品后设置购买次数和货币，0 次不购买；没有购买预算设置。

已适配金币、普通钻石和星片。为保持旧配置下标，英雄水晶货币位置标注为暂未适配；配置该货币会使商店任务报错停止，不会扣款。“英雄水晶”商品本身仍可按其实际钻石价格购买。脚本拒绝付费钻石、现金及召唤商品。每次仅购买 1 份，重复前重读商品、价格、余额、库存；余额变动与价格不一致时停止，未知结果不重复提交。

预设数据在 `agent/shop_products.json`，修改后执行 `python dev/update_shop_products.py`。扫荡选项独立设置节点由 `python dev/update_sweep_options.py` 生成。

## 运行结束

进化石选项中的“起始属性”“英雄选择”对应上文两种刷取模式；详细规则见任务说明和选项提示。

关闭游戏是可单独勾选的运行项，应放在游戏任务末尾。退出助手使用 MFAAvalonia 自带的 **设置 → 启动设置 → 结束后操作 → 关闭本程序**；保留还是退出由用户当前设置决定。

启动器优先使用包内 Python，并在打开 GUI 前检查 .NET 与关键文件；源码部署没有包内 Python 时使用 PATH 中的 `python`。关于、项目反馈和许可证页面包含 MGA 名称及框架来源。源码版本更新不会直接替换正在运行窗口的文字，重新启动后加载。

## 截图与识别频率

EmulatorExtras 是 MaaFramework 的模拟器增强截图通道，开发机 MuMu 测得约 4～7ms。它不是游戏帧率，也不代表 OCR 和动作的完整耗时。

GUI 实时画面刷新率在实时视图设置中调整。主资源“识别轮询间隔”支持 50～2000ms，默认 100ms。Agent 按流程需要截图，并不持续按固定 FPS 采集。更换设备时重新选择其支持的截图方式。

## 开发与验证

```powershell
python dev/validate_project.py
python -m unittest discover -s dev -p "test_*.py"
```

以上为引用、参数和决策验证；原生参数测试需要本机 MaaFramework 运行库，纯源码环境会注明跳过。截图回放依赖开发机未提交的游戏截图，不能把测试数量当作全部页面实机通过。

```powershell
# 需要本机截图样本，不点击设备
python dev/check_recognition.py
# 会连接模拟器，不能与 GUI 任务同时运行
python dev/run_task.py GT_EnsureHub
```

`interface.json` 定义页面任务与选项，`resource/pipeline/` 定义流程，`agent/` 读取计数与费用。`dev/` 为验证工具和实测记录；`dev/public-readiness.md` 记录本次公开前检查范围。

## 验证范围与已知限制

截至 **2026-10-29**，本地 80 项测试和任务引用检查通过；不含运行库的纯源码副本运行 74 项测试通过，原生测试组明确跳过。实机复验覆盖：

- 大厅、签到与灵魂点、公会、邮件、好友、通用免费次数检查、日常奖励、通行证，共 8 个入口正常结束。其中当日免费次数已用完的副本正常跳过，不代表本轮重新完成了扫荡。
- 活动奖励领取成功获得 200 积分。
- 商店已领取免费金币及售罄商品正常跳过，强化锤确认框正确预览后取消；本轮没有执行收费商品购买。
- 进化石和开花石均实测 0 次跳过；非零体力扫荡的历史实测与边界测试见开发记录。

适配范围是已记录的游戏版式，不包含所有限时活动、挑战战斗或登录异常。自动换英雄在刷满瞬间的实机样本仍有限；推广页“2 周内不再提示”的长期效果仍需观察。进化石长标题已依据用户截图修正，重启后布局与不同窗口尺寸仍需继续观察。详细证据见 [公开前检查记录](dev/public-readiness.md)。

## 常见问题

| 现象 | 检查方式 |
| --- | --- |
| 连接失败、没有截图 | 确认模拟器已启动、ADB 已启用，重新发现并选择当前实例；核对实际端口，避免其它脚本同时控制 |
| 启动器提示 Python 不存在或 Agent 无法启动 | 检查 `python --version`；在 `interface.json` 和启动器中使用同一可用 Python 命令 |
| GUI 提示缺少 .NET 或原生 DLL | 检查 .NET 10 x64 Runtime，以及完整的 GUI、`libs/`、`runtimes/` 文件 |
| 更新后文字、任务或选项仍是旧版 | 退出助手后通过 `run_gui.bat` 启动，保留 `config/` 中的用户设置 |
| 商品已勾选却没有购买 | 检查分类是否开启、购买次数是否大于 0、货币是否匹配；日志会区分售罄、已领取和余额不足 |
| 任务在未知页面停止 | 保留任务名、错误日志与截图，反馈到 [Issues](https://github.com/Turingkb/GuardianTalesAuto/issues)，不要反复提交可能扣费的动作 |

仓库不保存个人配置、日志、完整账号截图、运行二进制和 OCR 模型。反馈前请遮盖个人信息；详细日志只提交定位问题所需的片段。
