# MGA 坎公助手

MGA 是基于 **MaaFramework** 自动化引擎和 **MFAAvalonia** 通用桌面界面的《坎公骑冠剑》国服日常助手，适配 `com.bilibili.snake`、1280×720 横屏。当前资源版本 **0.3.1**，验证环境为 Windows x64、MuMu。

> 本仓库提供源码、任务与识别资源，不是解压即用的完整运行包。活动与游戏界面可能变化，已验证范围和剩余限制见下文。

## 架构来源与致谢

- [MFAAvalonia 2.16.2](https://github.com/MaaXYZ/MFAAvalonia/tree/v2.16.2)：Avalonia 桌面界面、任务选项、日志、设置、运行后操作，GPL-3.0。

MGA 在上述架构上维护坎公任务、模板、配置和 Python Agent。感谢上游开发者与贡献者；替换程序名称和图标不改变框架来源。完整范围、上游源码及许可见 [第三方声明](THIRD_PARTY_NOTICES.md)。

## 安装与使用

1. 安装 Windows x64 Python 3.10 或以上，并将 `python` 加入 PATH；开发机使用 Python 3.14。安装与 MFAAvalonia 2.16.2 匹配的 .NET 10 桌面运行时。
2. 从上述官方固定版本取得 MFAAvalonia 与 MaaFramework 运行文件。按 [环境恢复说明](dev/repository-setup.md) 放置 GUI、原生库、输入辅助组件及 OCR 模型，保留各自许可证。
3. 启动模拟器，游戏设为 1280×720 横屏。双击 `run_gui.bat`；首次导入时启动器会将 `MFAAvalonia.exe` 改名为 `GTAssistant.exe`。依赖 DLL 保留原名。
4. 在 GUI 选择自己的 ADB 设备；MuMu 实例、端口和安装目录由本机实际配置决定，不能照搬开发机路径。
5. 按需要选择任务、设置次数和商品，点击开始。默认 10 项日常，体力副本与付费游戏货币商品不会默认开启购买。

不要让 GUI、CLI、其它脚本或开发工具同时控制同一模拟器。首次启动可以只选择“启动并返回大厅”确认连接。GUI 已打开时，启动器会延后缓存迁移；任务或界面更新后，在方便时重新通过 `run_gui.bat` 启动。

## 功能

共 **21 项任务，默认 10 项**。游戏内“已领取”或“免费次数用完”可正常跳过；未知页面、费用异常和无法确认的结果会停止相关任务并保留日志。

| 任务 | 默认 | 范围 |
| --- | --- | --- |
| 启动并返回大厅 | 开 | 启动游戏，处理已识别的公告、推广及奖励弹窗 |
| 签到检查与领取 | 开 | 检查签到，签到前后收取浮游城灵魂点；已签到也收取 |
| 公会签到 | 开 | 公会签到及已适配排名结算 |
| 商店购买 | 开 | 默认每日免费金币；收费商品需勾选并填写次数 |
| 活动商店购买 | 关 | 独立商品勾选；未开放或售罄跳过 |
| 邮箱自动领取 | 开 | 系统与通知邮件、领取确认 |
| 好友一键领取与送礼 | 开 | 领取礼物并向现有好友送礼 |
| 通用日常扫荡 | 开 | 觉醒、忒提斯各自剩余免费次数，各最多 3 次；无免费次数跳过 |
| 进化石副本扫荡 | 关 | 次数、焕发限制、起始属性、自动选英雄或沿用游戏设置 |
| 金币／经验／道具副本扫荡 | 关 | 各自设置 0～100 次，默认只用焕发次数 |
| 红色碎片副本扫荡 | 关 | 保留焕发限制入口；没有焕发则默认跳过 |
| 开花石副本扫荡 | 关 | 次数与属性，奖励英雄沿用游戏设置，每次 10 体力 |
| 领取已完成的日常奖励 | 开 | 日常任务、活跃度奖励，返回大厅后领取可用的小公主宝箱 |
| 活动奖励领取 | 开 | 已适配“开心宾果乐”的任务积分；不抽奖、不兑换 |
| 领取通行证奖励 | 开 | 邀请赛目标经验、已解锁奖励；不购买或跳级 |
| 活动页面（查看） | 关 | 只打开列表供手动查看，不执行挑战或兑换 |
| 冷启动游戏（维护） | 关 | 停止后重新启动游戏 |
| 全屏 OCR 探测（调试） | 关 | 只识别当前画面，不点击 |
| 关闭游戏 | 关 | 只关闭坎公，保留模拟器和助手 |

推荐顺序：签到／商店／邮箱／好友 → 扫荡 → 日常奖励 → 活动奖励 → 通行证奖励 → 关闭游戏。任务可以拖动排序。

## 扫荡设置

次数为 0 时跳过。资源与进化石等副本共用游戏每日焕发次数，默认只使用剩余额度，任务顺序决定额度分配。关闭焕发限制后会消耗普通体力；游戏可能同时扣除备用体力，提交前会核验总消耗。免费觉醒和忒提斯不会使用付费挑战次数。

进化石“自动选英雄”从起始属性开始，仅选择已持有英雄；满星或累计达到 1160 个进化石时更换目标。每次扫荡后重新检查，当前属性没有目标时按虚→光→暗→土→火→水轮换，不执行英雄进化。“沿用游戏设置”只刷所选属性，需先在游戏奖励设置的齿轮中选好英雄。

开花石按所选属性与次数运行，不自动更换奖励英雄。两项副本各自保存次数和属性，不互相覆盖。

## 商店设置

资源提供体力、每日免费金币；英雄成长提供传说觉醒石；装备提供强化锤。钻石商店和活动商店保留预设商品及备用自定义商品。勾选商品后设置购买次数和货币，0 次不购买；没有购买预算设置。

已适配金币、普通钻石和星片。为保持旧配置下标，英雄水晶货币位置标注为暂未适配，选择后不会购买。脚本拒绝付费钻石、现金及召唤商品。每次仅购买 1 份，重复前重读商品、价格、余额、库存；余额变动与价格不一致时停止，未知结果不重复提交。

预设数据在 `agent/shop_products.json`，修改后执行 `python dev/update_shop_products.py`。扫荡选项独立设置节点由 `python dev/update_sweep_options.py` 生成。

## 界面与运行结束

进化石的长标题已缩短为“起始属性”“英雄选择”，选项为“自动选英雄”“沿用游戏设置”，详细解释在任务说明与选项提示中。开花石原有文字布局保持不变。

关闭游戏是可单独勾选的运行项，应放在游戏任务末尾。退出助手使用 MFAAvalonia 自带的 **设置 → 启动设置 → 结束后操作 → 关闭本程序**；保留还是退出由用户当前设置决定。

关于、项目反馈和许可证页面包含 MGA 名称及框架来源。源码版本更新不会直接替换正在运行窗口的文字，重新启动后加载。

## 截图与识别频率

EmulatorExtras 是 MaaFramework 的模拟器增强截图通道，开发机 MuMu 测得约 4～7ms。它不是游戏帧率，也不代表 OCR 和动作的完整耗时。

GUI 实时画面刷新率在实时视图设置中调整。主资源“识别轮询间隔”支持 50～2000ms，默认 100ms。Agent 按流程需要截图，并不持续按固定 FPS 采集。更换设备时重新选择其支持的截图方式。

## 开发与验证

```powershell
python dev/validate_project.py
python -m unittest discover -s dev -p "test_*.py"
```

以上为引用、参数和决策验证；原生参数测试需要本机 MaaFramework 运行库，纯源码环境会注明跳过。截图回放依赖开发机未提交的游戏截图，不能把测试数量当作全部页面实机通过。

```powershell
# 需要本机截图样本，不点击设备
python dev/check_recognition.py
# 会连接模拟器，不能与 GUI 任务同时运行
python dev/run_task.py GT_EnsureHub
```

`interface.json` 定义页面任务与选项，`resource/pipeline/` 定义流程，`agent/` 读取计数与费用。`dev/` 为验证工具和实测记录；`dev/public-readiness.md` 记录本次公开前检查范围。

## 已知限制

适配范围是已记录的游戏版式，不包含所有限时活动、挑战战斗或登录异常。自动换英雄的边界决策有测试，刷满瞬间的实机样本仍有限。推广页“2 周内不再提示”已做识别适配，其再次弹出后的长期效果仍需观察。截图接口暂不可用时，界面文字重叠须结合用户提供的截图检查，不能宣称已完成全部窗口尺寸的视觉验收。

仓库不保存个人配置、日志、完整账号截图、运行二进制和 OCR 模型。反馈前请遮盖个人信息；详细日志只提交定位问题所需的片段。
